# Hook capture examples

Example skills that send every finished turn of an agent session to Coolhand with `coolhand capture-turn`. See [docs/hook-capture.md](../../docs/hook-capture.md) for how it works.

These files are examples only. They are not published to npm (`package.json` `files` is a whitelist that does not include `examples/`) and are not compiled. The Claude Code example's frontmatter and hook command are checked by `test/hooks/skill-frontmatter.test.ts` (strict YAML and `sh -n`); the Cursor hook command is only syntax-checked (`sh -n`, in `test/hooks/hook-command.test.ts`), with no behaviour tests, while the Copilot hook file is parsed strictly (`test/hooks/copilot-hook-config.test.ts`) and its command is run against fake binaries. They are laid out as plain folders, not as `.claude/`, `.cursor/` or `.github/` directories, so the agents don't load them as real skills when you open this repo. Copy the one you want into your own project at the path shown.

| Agent | Copy to | Status |
|-------|---------|--------|
| [Claude Code](./claude/SKILL.md) | `.claude/skills/qa-example/SKILL.md` | **Works** (verified in a live headless Claude Code run). The skill carries its own `Stop` hook. Read the caveats in [docs/hook-capture.md](../../docs/hook-capture.md): the frontmatter must be strictly valid YAML or the hook is silently dropped, `--resume` doesn't re-register it, and with `async: true` the last turn of a headless run is lost. |
| [Cursor](./cursor/SKILL.md) + [hooks.json](./cursor/hooks.json) | `.cursor/skills/qa-example/SKILL.md`, `~/.cursor/hooks.json` | **Not working yet.** `capture-turn` has no Cursor adapter and `capture-setup` does not exist. |
| [VS Code Copilot](./copilot/SKILL.md) + [coolhand-capture.json](./copilot/coolhand-capture.json) | `.github/skills/qa-example/SKILL.md` with `coolhand-capture.json` beside it | **Works in VS Code on recorded and live sessions; some parts unverified** (see the doc). Copilot skills cannot carry hooks, so the skill's Step 0 installs the hook file into `~/.copilot/hooks/` for the user, with a plain-language explanation, then asks for a new chat. [workspace/coolhand-capture.json](./copilot/workspace/coolhand-capture.json) is the alternative: commit it as `.github/hooks/coolhand-capture.json` and each person opts in with `COOLHAND_CAPTURE_API_KEY`. See [docs/hook-capture.md](../../docs/hook-capture.md#vs-code-copilot). Windows and the `command`/`powershell` keys are untested. |

Cursor and Copilot cannot attach a hook to a skill; hooks there live in config files. For Copilot that file is the working example above. The Cursor example shows the shape a self-installing design is aiming for: the skill's first step would run a `coolhand capture-setup` command that writes the config file and enrolls the session. It does not exist yet, so the Cursor config is a reference only.

Replace `YOUR_PUBLIC_API_KEY` in every file with your Coolhand **public** API key. It can write request logs and cannot read anything back.
