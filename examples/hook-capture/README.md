# Hook capture examples

Example skills that send every finished turn of an agent session to Coolhand with `coolhand capture-turn`. See [docs/hook-capture.md](../../docs/hook-capture.md) for how it works.

These files are examples only. They are not published to npm (`package.json` `files` is a whitelist that does not include `examples/`) and are not compiled. The Claude Code example's frontmatter and hook command are checked by `test/hooks/skill-frontmatter.test.ts` (strict YAML and `sh -n`); the Cursor skill gets the same checks (strict YAML, `sh -n`, and the command run against fake binaries), while the Copilot hook file is parsed strictly (`test/hooks/copilot-hook-config.test.ts`) and its command is run against fake binaries. They are laid out as plain folders, not as `.claude/`, `.cursor/` or `.github/` directories, so the agents don't load them as real skills when you open this repo. Copy the one you want into your own project at the path shown.

| Agent | Copy to | Status |
|-------|---------|--------|
| [Claude Code](./claude/SKILL.md) | `.claude/skills/qa-example/SKILL.md` | **Works** (verified in a live headless Claude Code run). The skill carries its own `Stop` hook. Read the caveats in [docs/hook-capture.md](../../docs/hook-capture.md): the frontmatter must be strictly valid YAML or the hook is silently dropped, `--resume` doesn't re-register it, and with `async: true` the last turn of a headless run is lost. |
| [Cursor](./cursor/SKILL.md) | `.claude/skills/qa-example/SKILL.md` (Cursor also loads this folder) | **Unverified.** Built from Cursor's documentation and run only against hand-written fixtures. The skill carries a `Stop` hook like the Claude one, but Cursor's docs do not say a skill's frontmatter hooks fire; if they do not, nothing is sent. Claude Code also loads `.claude/skills/`, so a copy there would be captured by both tools under `--agent cursor`; see the doc. See [docs/hook-capture.md](../../docs/hook-capture.md#cursor-unverified). |
| [VS Code Copilot](./copilot/SKILL.md) + [coolhand-capture-example.json](./copilot/coolhand-capture-example.json) | `.github/skills/qa-example/SKILL.md`; the hook file is written to `~/.copilot/hooks/coolhand-capture.json` by the skill's Step 0 | **Works in VS Code on recorded and live sessions; some parts unverified** (see the doc). Copilot skills cannot carry hooks, so the skill's Step 0 writes one generic hook file into `~/.copilot/hooks/` for the user, with a plain-language explanation, then asks for a new chat. The hook's `--skill` is a name or a pattern (`'*'`, `'acme-*'`, `'qa-*\|other'`), so the same file and the same Step 0 serve every skill in a library (patterns: unit-tested, not yet run in a live chat). [workspace/coolhand-capture-example.json](./copilot/workspace/coolhand-capture-example.json) is the alternative: commit it as `.github/hooks/coolhand-capture.json` (filling in `YOUR_SKILL_PATTERN`) and each person opts in with `COOLHAND_CAPTURE_API_KEY`. See [docs/hook-capture.md](../../docs/hook-capture.md#vs-code-copilot) and [docs/hook-capture-skills-library.md](../../docs/hook-capture-skills-library.md). Windows and the `command`/`powershell` keys are untested. |

Copilot cannot attach a hook to a skill; its hook lives in a config file, and the working example above installs one. Cursor has no `hooks.json` example on purpose: a `hooks.json` hook runs for every chat, and nothing known about Cursor's transcript lets `capture-turn` tell the skill's chats from the rest.

Replace `YOUR_PUBLIC_API_KEY` in every file with your Coolhand **public** API key. It can write request logs and cannot read anything back.
